# 구조 자기 점검 / 構成セルフチェック

위에서 아래 순서로 본다. 구조 항목(A·B)이 하나라도 실패하면 문체 점검(patterns-*.md)으로 넘어가지 않고 먼저 고친다.

## A. 결론이 첫 화면에 있는가 (가장 중요)

- [ ] 제목 바로 아래 첫 섹션이 결론이다 (`결론`/`結論`. 사용자설명서는 `이 문서로 할 수 있는 것`/`この文書でできること`, 작업보고는 `결과`/`結果`, 회의록은 `결정 사항`/`決定事項`).
- [ ] 결론이 3줄 이내다. 5줄을 넘으면 실패.
- [ ] 결론만 읽고 멈춰도 핵심(무엇이 결론인지 / 무엇을 고르라는지 / 무엇을 하라는지)을 알 수 있다.
- [ ] 결론이 "중요하다", "검토가 필요하다", "本質的だ", "鍵となる" 같은 추상어로 끝나지 않는다. 끝나면 무엇을 할지로 바꾼다.
- [ ] 선택지를 제시했다면 하나를 추천했고 이유가 한 줄 있다. 정보가 부족하면 조건부 추천("추천: A. 단, 예산이 X 이상이면 B")으로 쓴다. 결론이 `[확인 필요]`로 시작하면 실패다 (작성 모드). 주어진 사실로 판단하는 것은 지어내기가 아니다.
- [ ] 사용자가 정할 것이 「결정 필요」/「要判断」에 모여 있고, 본문 곳곳에 흩어져 있지 않다.
- [ ] 독자가 할 일이 구체적이다. "확인 부탁드립니다"/「ご確認ください」만으로 끝나지 않고 무엇을 확인해 어떻게 하면 되는지 쓰여 있다.

## B. 흐름과 반복

- [ ] 각 섹션 첫 문장만 이어 읽어도 문서 흐름이 이해된다.
- [ ] 근거는 3~4개다. 5개 이상이면 겹치는 것을 묶는다 (피라미드 원칙).
- [ ] 근거끼리 겹치지 않고, 결론을 지지하는 데 빠진 근거가 없다.
- [ ] 같은 내용을 결론·본문·마무리에서 다시 쓰지 않았다. 마지막 섹션이 "정리하면"/"以上をまとめると"로 시작하는 요약이 아니다.
- [ ] 한 문단에 한 주제다. 8줄을 넘는 문단은 나눈다.
- [ ] 비교(선택지·설정값·전후)는 문장이 아니라 표다.
- [ ] 사실(확인한 것)·가정(확인하지 않은 것)·제안(하자는 것)이 한 문장에 섞여 있지 않다.

## C. 문서 종류별

- [ ] 검토자료: 「선택지 비교」 표가 있고 추천안이 표에 표시되어 있다.
- [ ] 조사자료: 결론에 "우리에게 의미하는 것"/"自分たちにとっての意味" 한 줄이 있다. 출처 표가 상세 끝에 있다.
- [ ] 사용자설명서: 번호 절차 사이에 개념 설명 문단이 끼어 있지 않다. 한 단계에 한 동작이다. 설정값은 표로 분리했다.
- [ ] 사용자설명서의 화면 절차: 화면마다 이미지와 번호표가 있고 목록 번호와 1:1이며, `manual-screens.md` 10절 점검을 통과했다.
- [ ] 설계서: 결론이 설계 방침이다. 대안은 「선택지 비교」 표로 있다.
- [ ] 기술 스택을 다루는 문서: 구성도·기술별 역할 표·연동 흐름이 있고 `tech-stack.md` 7절 점검을 통과했다.
- [ ] 작업보고: 완료·미완료·다음 행동이 모두 있다. 검증하지 않은 것을 완료로 쓰지 않았다.
- [ ] 회의록: 결정 사항과 할 일(담당·기한)이 논의 요지보다 앞에 있다.

## D. 독자

- [ ] 독자(audience)가 모를 용어를 풀이 없이 쓰지 않았다. `stakeholder`·`end-user`는 처음 나올 때 한 줄로 푼다.
- [ ] `stakeholder`·`end-user` 문서의 수치에 "그래서 좋은지 나쁜지"가 붙어 있다.
- [ ] 독자에게 왜 중요한지가 결론 또는 배경에 있다.

## E. 상세도

- [ ] `short`: 결론·결정 필요·근거(항목당 1줄)만 있다. 상세 섹션이 없다. 검토자료는 근거 대신 선택지 비교 표를 둔다 (같은 사실을 두 번 쓰지 않도록).
- [ ] `normal`: 골격 전체가 있고, 상세는 결정에 필요한 것만이다.
- [ ] `detailed`: 깊이를 예시·절차·근거·비교표·이유로 더했다. 같은 말을 다른 말로 다시 쓴 문단이 없다.
- [ ] 판본 변환(자세히 → 요약 등)이면 결론과 결정 필요 문구가 원본과 글자 그대로 같다.

## F. 불변식 (윤문 모드에서 특히)

- [ ] 원문에 없는 사실·숫자·고유명사·추천을 새로 만들지 않았다.
- [ ] 숫자·인용·부정 표현을 지우거나 바꾸지 않았다.
- [ ] 뜻이 뒤집힌 문장이 없다 (특히 이중 부정, 조건문).
- [ ] 코드 블록·표 안의 데이터를 바꾸지 않았다.
- [ ] 템플릿의 `<!-- -->` 안내 주석을 남기지 않았다.
