# 전달 원칙 / 伝達の原則

원문을 옮기지 않고 요점만 새로 썼다. 각 원칙이 템플릿·자기 점검 어디에 반영되었는지 함께 적는다.

## 문서 종류별 매핑

- **보고서·검토자료** (`review`): 결론 = 피라미드 꼭대기. 결론 → 결정 필요 → 배경(S·C·Q 2~3줄) → 근거 3~4개. 근거 각 항목의 첫 문장이 그 근거의 요지.
- **조사자료** (`research`): 위와 같고, 결론에 "우리에게 의미하는 것" 한 줄. 조사 출처는 상세 끝에 표로.
- **사용자설명서** (`manual`): Diátaxis 작업 방법을 기본으로 한다. 개념 설명은 절차 사이에 끼우지 않고 「알아 둘 것」 섹션이나 별도 문서로 분리해 링크한다. 설정값·항목 목록은 레퍼런스 표로.
- **설계서** (`design`): 결론(설계 방침) → 결정 필요 → 근거(왜 이 구조인가) → 선택지 비교 → 상세.
- **작업보고** (`report`)·**회의록** (`minutes`): 결과·결정 사항을 맨 앞에. 사실(한 일)·가정·제안(다음 행동)을 섞지 않는다.

## 「자세히」에서 깊이를 더하는 방법

`detailed`는 아래 수단으로만 깊이를 더한다. 같은 말을 다른 말로 다시 쓰지 않는다.

- **추상 → 구체**: 원칙을 말한 직후 실제 예시(코드, 화면, 수치, 명령)를 붙인다.
- **단계 분해**: 절차는 번호 목록으로 한 단계에 한 동작. 각 단계에 "확인 방법"을 붙인다.
- **비교는 표로**: 선택지·설정값·전후 비교는 문장 대신 표.
- **이유**: 결정마다 "왜 이렇게 했는가"를 한 문장으로.
- **예상 질문**: 독자가 물을 만한 질문 2~3개를 끝에 「자주 묻는 질문」/「よくある質問」으로. 본문에서 이미 답한 것은 넣지 않는다.
- **그림**: 구조·흐름은 Mermaid 다이어그램을 먼저 검토한다.
